# Pin Atlas

A customizable microcontroller and development-board directory with interactive pinouts. Vanilla HTML, CSS and modular JavaScript; no framework, database, paid service or dependency installation is needed.

## Included

- A searchable homepage with board/chip, manufacturer and pin-function filters; grid and list views.
- Separate device pages with SVG pinouts, hover/focus details, click/tap selection, multi-function highlighting, peripheral-instance filtering and searchable pin tables.
- Specifications, mapping limitations, exact package/revision labels and manufacturer references.
- Browser-local light/dark/system themes, three accents and compact cards.
- One JSON record per device, validation, a template generator and automatic catalog indexing.
- A GitHub Actions workflow for GitHub Pages; hash routes and relative paths work under repository subpaths.

The starter catalog has **14 entries**, not every microcontroller ever produced. It includes Arduino UNO R3, classic Nano, Raspberry Pi Pico/Pico W/Pico 2, ESP32-DevKitC V4 with WROOM-32, ATmega328P PDIP-28, ATtiny25/45/85 PDIP-8, ATtiny24A/44A/84A PDIP-14, and STM32F103C8T6 LQFP-48. Pin maps cover the displayed physical pins and common functions. See each device's sources for exhaustive electrical data and alternate-function tables.

## Run and build

Requires Node.js 20 or later for tooling. The published site itself runs in a modern browser.

```bash
npm test
npm run build
```

Serve `dist/` with any HTTP server or preview extension. For example:

```bash
python3 -m http.server 8000 --directory dist
```

Open `http://localhost:8000`. Opening `index.html` via `file://` cannot fetch the JSON catalog. `data/catalog.json` is generated by the build; build again after adding or removing a device.

## Publish to GitHub Pages

1. Create a repository, for example `pin-atlas`, and upload **the contents of this folder** to its root. Include `.github/workflows/pages.yml`; a hidden-folder-aware file upload or Git is needed.
2. Use `main` as the default branch, or update the workflow branch name.
3. Open the repository's **Settings → Pages** and set **Source → GitHub Actions**.
4. Commit or push a change to `main`, or run the `Publish Pin Atlas to GitHub Pages` workflow manually from **Actions**.
5. After the workflow succeeds, the site is at `https://YOUR-USERNAME.github.io/pin-atlas/`. A repository called `YOUR-USERNAME.github.io` uses the account root instead.

No secret or access token belongs in the source. The workflow uses GitHub's built-in job permissions. The project is prepared for publication; a local build does not mean it has been uploaded or deployed.

For a new empty repository, local Git upload commands are:

```bash
git init
git add .
git commit -m "Build Pin Atlas catalog and interactive pinout explorer"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/pin-atlas.git
git push -u origin main
```

Authenticate through your normal GitHub client. Do not paste credentials into the code.

## Future updates

Read [docs/CUSTOMIZATION.md](docs/CUSTOMIZATION.md) for the data format, theme configuration and extension points. Start a new record with:

```bash
node scripts/new-device.mjs exact-model-package
```

Replace all placeholders with manufacturer-verified data before committing. Run tests and build, then push. Adding an ordinary board, DIP or QFP entry does not require editing `app.js`.

## Verification

`npm test` checks catalog validity, fixed interface highlights, Pico physical/GPIO numbering, ESP32 default routes and flash reservations, tinyAVR USI labeling, STM32 package orientation, and subpath-compatible asset references. `npm run build` validates every device and produces the static output. Browser visual and interaction QA has not been performed in the creation environment; test the UI on desktop and mobile before treating the release as visually approved.

## Data and attribution

Diagrams are original schematic illustrations, not to scale. Manufacturer documents are linked, not republished. Manufacturer names and trademarks belong to their owners. This project is an independent reference. Each record states coverage, sources and its review date. Never infer that highlighting several functions makes them simultaneously usable.

There is no backend or remote editor. Future content updates are made through source JSON files and Git commits. A future admin editor, comparison tool, additional package renderer, or CMS can be added without replacing the data model.
